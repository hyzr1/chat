# Hyzr Chat diligence brief

## Thesis

The unit of value is an accepted engineering outcome, not a model response. Hyzr Chat routes each part of a delivery to the least expensive eligible specialist, keeps execution durable, verifies the result independently, and learns from acceptance and human edits.

## What exists today

- Durable encrypted jobs, leases, checkpoints, retries, reconnecting event streams, cancellation, and recovery.
- Capability-specific routing across Claude and ChatGPT with explicit provider constraints and configurable priorities.
- Deterministic zero-model execution for an exact safe allowlist of mechanical tasks.
- Per-delivery contracts, measured token ceilings, bounded context packets, and live budget evidence.
- Repository intelligence, workspace memory, specialist handoffs, and isolated GitHub worktrees.
- GitHub App and Linear adapters with signed-webhook and replay protection.
- Independent tests, production audit, credential scan, desktop/mobile browser flows, screenshots, and accessibility evidence.
- Shared desktop/mobile projects and tasks, LAN preview addressing, and token-protected device pairing.
- Matched evaluation infrastructure with repeated trials, Wilson intervals, pricing calibration, and exportable evidence.

## What is not yet proven

- There is not yet a statistically useful customer sample demonstrating lower cost per accepted task than a premium-only baseline.
- SQLite is a strong single-operator queue, not a multi-tenant hosted control plane.
- Local provider subscriptions do not expose perfect real-time cost or token enforcement; usage can arrive after a call completes.
- Automated verification does not eliminate human security, accessibility, or product review.
- The current product has pilot access control, not enterprise SSO, RBAC, tenant isolation, or compliance certification.

## Defensible metrics

Hyzr Chat should lead fundraising with four measured curves:

1. Acceptance rate versus cost per accepted task.
2. Human edit distance versus task complexity.
3. Time to verified pull request versus baseline workflow.
4. Routing improvement as rated outcomes accumulate.

Every result should include sample size, task set, model versions, pricing assumptions, trial count, confidence interval, and failure handling. Rejected work must remain in the success-rate denominator.

## Moat hypothesis

Model access is not the moat. The compounding asset is the outcome graph connecting repository state, task shape, selected specialist, execution trace, verification evidence, reviewer edits, and acceptance. That data can improve routing and delivery contracts while remaining provider-neutral.

## Near-term milestones

### Design-partner ready

- Three repositories connected through GitHub App.
- Fifty representative tasks with explicit accept/reject feedback.
- Twenty matched Hyzr Chat versus premium-only cases under controlled budgets.
- Reliable phone supervision through disconnect and server restart drills.

### Seed-ready evidence

- At least two design partners repeatedly using Hyzr Chat on real backlog work.
- A reproducible improvement in cost per accepted task without lower acceptance.
- A clear weekly retention and task-volume story.
- Hosted sandbox prototype with identity, tenant isolation, quota enforcement, and centralized observability.

## Risk register

- **Quality regression from cheap routing:** gate adaptation on rated evidence and verify independently.
- **Runaway token consumption:** exact native paths, bounded context, tiered runtime limits, delivery ceilings, and evaluation ceilings.
- **Provider volatility:** preserve provider constraints and benchmark by capability rather than hard-coding one universal winner.
- **Local-machine security:** require pairing on LAN, sign webhooks, encrypt secrets, scan credentials, and avoid public exposure.
- **Demo success mistaken for product traction:** separate technical readiness, benchmark evidence, and customer adoption in every pitch.
